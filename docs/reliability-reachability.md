## 二、热不稳定的确可达 ✓

枚举 **252 种合法配置**（CPU × 散热 × 机箱 × 电源 × 显卡）：

| 项 | 值 |
| --- | --- |
| 最低冷却比 | **0.97** |
| 热不稳定（冷却比 < 1）的组合 | **6 / 252** |

**所以 ×3 与 ×2 两个倍率会触发** ✓ 第 116 轮把「散热一票否决」改成「扣分」是**有意义的** ✓ 那 6 种配置以前会被直接拒单，现在只是做得慢、更贵 ✓

## 三、但**供电余量的倍率永不触发** ✗

| 项 | 值 |
| --- | --- |
| 模型里的阈值 | **0.2** |
| 252 种配置的供电余量 | 最低 **0.310**，十分位 0.360，中位 0.590，最高 0.860 |
| 低于 0.2 的组合 | **0 / 252**（一个都没有） |

**所以 `powerHeadroomBelowThreshold` 这个数是死数据** ✗ 它被读取（`check:wiring` 过得了）✓ 但**永远不会真的生效** ✓

**后果**：故障率只可能是两个值——基础 0.04，或热不稳定时的 0.24 ✓ 供电紧张**从来不会让机器更容易坏** ✓

### 若要让这项生效，阈值要抬到多少

| 阈值 | 会触发的组合 |
| ---: | ---: |
| 0.20（现在） | 0 / 252，仍然一个都不触发 |
| 0.30 | 0 / 252，仍然一个都不触发 |
| **0.35** | **13 / 252（5%）** ✓ |
| 0.40 | 26 / 252（10%） |
| 0.45 | 51 / 252（20%） |

**建议把阈值从 0.2 抬到 0.35** ✓ 理由：

1. 它让「为了省钱选小电源」变成一个**有代价的选择** ✓ 现在选小电源是纯赚 ✓
2. 5% 的组合占比不大 ✓ 不会把普通配置也卷进去 ✓
3. 它让设计里已经写好的一条规则**真的开始工作** ✓

**但这一项改变平衡数值** ✗ 所以我不擅自改，等你定 ✓

## 四、这是一类新的问题：**读了但不可达**

| 校验 | 能发现吗 |
| --- | --- |
| `check:wiring` | **不能** ✗ 它验证「设计里的数被机制读取」✓ 而阈值**确实被读了** ✓ |
| `check:seams` | **不能** ✗ 同理 |
| **本轮的人工枚举** | **能** ✓ 把全部合法配置跑一遍，看条件是否可达 ✓ |

**「被读取」与「会生效」是两件事** ✗ 与第 113、114、120 轮那类「看起来在检查、其实没检查」同源 ✓

## 五、建议：把可达性做成一条校验

| # | 内容 |
| --- | --- |
| **N** | **加一条可达性校验**：枚举合法配置，检查 `reliability-model.json` 里每个条件倍率**至少有一种配置能触发** ✓ 否则说明它是死数据 ✓ |

**这条能防止「设计里写了、永远不会发生」的数** ✓ 而现有的 28 个校验一个都管不到 ✓
