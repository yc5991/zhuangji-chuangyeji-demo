# 「别差太多」——把这句话变成一条可检查的标准

## 你的话

> 「意思就是随便设计数值**只要不是差太多**就行了」

**所以「混合永远最赚」不是一条规则** ✗ 你要的是「**三条路线别差太多**」✓

**这是一个可以量化的标准** ✓ 我把「差多少」测出来了，并做成一条校验。

| 项 | 值 |

| 出货数据的差距 | 23—26% |

**全部不超过四成** ✓ 而且**完整版的差距随年份变大**（23% → 38%）✓ ——后期选择更重要，这是好的 ✓

## 4 已做成校验

`check:difficulty` 现在多了一条：

> **同一难度下，三条路线的总利润差距不得超过最高者的 45%** ✗ 超过就失败 ✓

**为什么定 45% 而不是 40%**：决定落地后实测是 39—40% ✓ 上限定在 45% 留一点余量 ✓ 既不会因为正常波动误报，也能抓住真正的失衡 ✓

**当前输出**：

    routeSpreadLimit: 0.45

**困难档排除在比较之外** ✓ ——它的非精品路线是**故意**要失败的（见上一轮的改动）✗ 算进来会得到 142% 的假报警 ✓

## 5 这条校验抓的是什么

| 情形 | 结果 |
| --- | --- |
| 某条路线被改得远远强于或弱于另外两条 | **失败** ✓ |
| 三条路线互有高低、但都在四成以内 | 通过 ✓ |

**所以它不再要求「哪条路线最高」** ✗ ——这与你的话一致 ✓

## 6 规格第 193 行需要你确认改法

**原文**：「混合路线的总利润高于两条单一路线」

**建议改成**：

> 三条路线的总利润应当接近，**差距不超过最高者的四成半**。哪条最高随年份变化：完整版里 15 年中有 10 年混合最高、5 年量产最高。

**这样规格和实测就一致了** ✓ 而且保留了完整版「什么时候该转路线」的深度 ✓
