# 工作台几何与配件尺寸

数值模型会判断「散热器太高装不进」「显卡太长装不进」「电源太深装不进」，依据是 `components.json` 里的机箱尺寸

但**机箱的占地面积在另一个文件里又记了一遍**：`workbench-geometry.json` 为每个机箱记录安放锚点与线缆通道，也用宽和高描述这个机箱

## 1 两处记录的是同一个事实，只是朝向不同

| 文件 | 字段 | 含义 |
| --- | --- | --- |
| `components.json` | `dimensionsMm` | 宽 × 高 × **深** |
| `workbench-geometry.json` | `width` / `height` | **深** × 高 |

逐项对照（第 66 轮实测）：

| 机箱 | 几何 宽×高 | 配件 深 / 高 | 一致 |
| --- | --- | --- | --- |
| 小型机箱 | 330×320 | 330 / 320 | 是 |
| 标准机箱 | 430×430 | 430 / 430 | 是 |
| 静音机箱 | 450×460 | 450 / 460 | 是 |

## 2 但**没有任何校验对照这两处**

读 `workbench-geometry.json` 的工具共五个（`check:cable-routing`、`check:references`、`check:single-source`、`check:wiring`、`prepare-demo`）——**没有一个拿它与配件里的机箱尺寸对照**

后果很具体：**在配件里改一个机箱的尺寸，工作台几何不会有任何反应**。数值上「装得下」的判定会跟着新尺寸变，而工作台显示的还是旧尺寸——两边说的不是同一台机箱

## 3 已补上

`check:cable-routing` 本来就同时读几何与配件，在那里加了三项断言：

1. 几何里的 `caseId` 必须在配件目录里存在
2. 几何的 `width` 必须等于配件的 `dimensionsMm.depth`
3. 几何的 `height` 必须等于配件的 `dimensionsMm.height`

## 4 已实测能抓到

把静音机箱的高度在配件里改成 999（几何文件不动）：

    case_quiet: the workbench is 460mm tall but the catalogue case is 999mm tall

恢复后立即通过。**以后改机箱尺寸必须两处一起改，否则当场失败**

## 5 边界说明

工作台的手工操作与碰撞检测属于交互与美术工作流。**本轮补的不是碰撞检测，而是「两个文件对同一台机箱的尺寸描述必须一致」**——这一条不成立时，数值上的装配判定就没有意义
