# 数值回归基线

标定好的平衡很容易被后续改动悄悄破坏——无论是自己重标、还是另一条工作流改了共享数据。基线把当前所有关键指标冻结成一份文件，之后任何改动都能一键看出影响了什么

## 1 用法

| 命令 | 作用 |
| --- | --- |
| `npm run baseline:diff` | 重新计算全部指标并与基线对比，列出每一处变化 |
| `npm run baseline:update` | 确认新数值，重新冻结基线 |

基线文件是 [平衡基线](../design/balance-baseline.json)。改完数值先跑 `baseline:diff`，确认每一处变化都是想要的，再跑 `baseline:update`

## 2 冻结的内容

| 分组 | 条目数 | 内容 |
| --- | ---: | --- |
| `runs` | 54 | 三档难度 × 全部情景 × 三条路线的利润、期末现金、是否破产、破产月份、销量 |
| `lossTolerance` | 3 | 每档的最差单月净流出与可承受亏损月数 |
| `investments` | 4 | 每项发展投资的边际利润 |
| `reliability` | 4 | 各样机的基础故障率 |
| `fullGame` | 15 | 2016—2030 年混合路线的利润 |

## 3 灵敏度实测

把预算办公样机的售价只提高 **5 游戏币**（约 0.24%），基线报出 **67 处变化**，覆盖三档难度与多个情景。恢复后立即回到 `unchanged`

这说明基线足够灵敏，不会漏掉小改动

## 4 与其他校验的分工

十个 `check:*` 校验守住的是**性质**：路线收益关系、难度顺序、投资必须回本、事件必须落在规定月份等。基线守住的是**数值本身**：性质没被破坏但数字变了，校验不会响，基线会

两者互补：性质类校验防止设计被破坏，基线防止标定被无意中改写
