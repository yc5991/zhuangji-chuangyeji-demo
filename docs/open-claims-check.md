# 新增校验：验证「待办清单」里的每一项确实还没做

第 108—109 轮发现四处「问题状态记录」过时 ✗ 规律是：**受校验保护的部分准确，不受保护的会过时** ✓

**本轮把这个规律变成一条校验。**

## 1 `npm run check:open-claims`

它**读设计文件里声明的待办项**，要求每一项都能指出「什么证据出现就说明它做完了」✓

| 情形 | 结果 |
| --- | --- |
| 待办项对应的数据**已存在** | **失败**——该项该从待办里删掉 |
| 待办项**没有指明证据** | **失败**——它又变回不可验证的散文 |
| 待办项确实还没做 | 通过 |

## 2 关键设计：**读文件，不读固定清单**

我第一版写错了 ✗ ——把 5 个已完成的项**硬编码在检查里**，结果第 109 轮我删掉它们后，检查**还在报这 5 项** ✗

    AssertionError: 5 items are listed as pending but the data shows they are done

**问题在于**：固定清单会像散文一样过时 ✗

**改成读文件后**：

| 行为 | 说明 |
| --- | --- |
| 从 `workbench.json` 读**当前**的 `pendingGeometry` | 文件改了，检查跟着改 |
| 每一项必须在处置表里有说明 | **新增待办项若没有处置方式，直接失败** |
| 有处置方式的，去数据里找证据 | 找到就是过时，找不到就是仍待办 |
