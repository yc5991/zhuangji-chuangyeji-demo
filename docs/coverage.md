# 校验覆盖矩阵

28 个校验、31 个设计文件——**但没有任何东西保证「每个数据文件都被某个校验读到了」**。一个新加的数据文件可以完全没有校验，而全部校验依旧全绿

`npm run check:coverage` 补上这一层元检查：**它不检查数据，它检查检查本身**

## 1 检查两条

**① 每个设计文件都必须被至少一个校验工具读取。** 读取可以是直接的，也可以是**间接的**——`check:investments`、`check:reachability` 等通过 `simulate-economy.cjs` 读数据，这一层会把模拟器读的 6 个文件计入它们的覆盖

**② 每个 check 工具都必须真的在读数据。** 一个不读任何设计文件的校验工具什么也没守住。元工具（读工具而不是读数据，如 `check-package`、`balance-baseline`、本检查自身）列入白名单

## 2 实测结果

| 项目 | 数量 |
| --- | ---: |
| 设计文件 | 26 |
| 校验工具 | 22 |
| 模拟器间接读取的文件 | 6 |
| **没有任何校验读取的文件** | **0** |

覆盖最薄的文件（只有 1 个校验读取）都是各自的专项校验，属于正常

## 3 已实测能抓到问题

放入一个没有任何校验读取的新文件 `design/experimental-tuning.json`，校验立刻报出：

    1 design files have no checker reading them: experimental-tuning.json

删除后立即回到通过。**从今以后，新增数据文件必须同时有东西读它，否则校验失败**

## 4 与导出覆盖的分工

两个「覆盖」检查的是不同的漏法：

| 检查 | 防的漏 |
| --- | --- |
| `check:export-coverage` | 文件**没进导出**——运行时读不到，改动也不会让基线失效 |
| `check:coverage` | 文件**没有校验**——数据错了没人发现 |

一份新数据文件要同时过这两关：既要有校验读它，也要在导出清单里分类
