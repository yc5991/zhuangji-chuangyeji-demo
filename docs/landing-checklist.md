## 3 两个需要「改写结论」而不是「更新数字」的地方

### 3.1 精品扩产的两个数字作废

`61956`（计划 ×1.5 的利润）与 `64733`（扩产上限利润）在方案下**不再成立**——精品被老板 96 小时设计工时封顶，扩产这条路走不通

**这两处必须改写结论**：从「精品扩产可以做到 ×1.5」改为「精品受老板 96 小时设计工时封顶，任何投资都无法扩产」

### 3.2 三方矛盾那一节要从「未解决」改成「已解决」

[Demo 详细设计候选](design-candidates.md) 的 4.2 节记录的是「四条规则无法同时成立」的证明过程。方案落地后矛盾解开，该节应改为**已解决记录**，保留证明过程作为设计依据

## 4 落地顺序

1. **写入数值**：`node tools/apply-decisions.cjs --apply`
   - 一次写入上述 13 处改动
   - **重跑全部 25 个校验；任何一个失败就停下，且不更新基线**
   - 全部通过后自动更新回归基线
2. **核对文档数字**：`npm run check:doc-figures`
   - 第 60 轮已把过时数字全部修好，并由这个校验自动看守
   - 落地后若它报出差异，说明文档需要跟着新数值更新
3. **改写 3.1、3.2 两节**（这一步需要人工，脚本做不了）
4. **更新完成度审计**：把已解决的条目从 `pending_decision` 改为 `complete`，加 `checker` 字段，删掉 `blockedBy`
   - `npm run check:audit` 会强制这个格式
5. **最终确认**：`npm run check:*` 全部通过 + `npm run baseline:diff` 报告 `unchanged`

## 5 为什么可以一次做完

| 风险 | 现在的防护 |
| --- | --- |
| 数值改漏 | `apply-decisions.cjs` 列出每一处改动，改完才写 |
| 改坏基线 | 校验不全过就**不更新基线** |
| 文档跟着过时 | `check:doc-figures` 自动发现 |
| 审计与决策包脱节 | `check:audit` 强制每个未完成项说明阻塞原因与决策人 |
| 实验改坏数据 | `tools/experiment.cjs` 在 `finally` 里恢复 |
