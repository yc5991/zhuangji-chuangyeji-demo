# 导出覆盖清单

`tools/prepare-demo.cjs` 负责把设计数据导出到运行时，并**为每个文件记录 sha256 指纹**——基线靠指纹判断「源数据变了没有」

它的 `sourceFiles` 是一张固定列表。**我在这几轮新建的 9 个数据文件都不在列表里**，意味着：

- 运行时拿不到这些数据（机箱选项、线缆走向、评价规则、故障模型、人员等级……）
- 改动它们**不会让基线失效**，等于没有版本保护

## 补上的分类

新建 [导出覆盖清单](../design/export-manifest.json)，把 `design/` 下**每一个 json 都显式分类**，由 `npm run check:export-coverage` 校验

| 类别 | 含义 | 数量 |
| --- | --- | ---: |
| 运行时输入 | 游戏要读的数据，**必须记入指纹** | 20 |
| 生成产物 | 由 prepare-demo 写出，**不能手改** | 2 |
| 工具产物 | 校验与分析的中间结果，不入包 | 4 |

补齐后 `sourceFiles` 从 **8 个增加到 17 个**，我新建的 9 个全部纳入指纹

## 校验强制项

`check:export-coverage` 会拒绝：**`design/` 里出现未分类的 json**（新文件不会被悄悄漏掉）、分类里有已经不存在的文件、类别名不合法、**运行时输入没被 prepare-demo 记录**、生成产物其实没有任何工具生成它、工具产物没有任何工具读它

**「未分类」这条是核心**：加进这份清单之前，新数据文件可以不声不响地不进导出。现在只要有新文件没分类，校验立刻失败

## 三份不属于数值策划的文件

`brands.json`、`product-series.json`、`art-runtime.json` 属于品牌与美术工作流。清单**记录**它们是运行时输入，但校验把它们列为 `reportedNotMine` **只报告不拦截**——是否导出、内容是否就绪由对应工作流决定

这样缺口不会被隐藏，也不会因为别的流没做完而挡住数值校验

## 仍未解决的问题

`sourceFiles` 只影响**指纹记录**。要让运行时真正读到这些数据，还需要把对应条目加进 `prepare-demo.cjs` 的导出对象。这一步改的是导出结构而不是文件清单，已记录为待办，由导出工具的负责人处理
