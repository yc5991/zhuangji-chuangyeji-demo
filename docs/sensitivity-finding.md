# 敏感度分析：设计工时是**唯一没有弹性的旋钮**

第 87 轮跑了 `npm run analyze:sensitivity`（**这个工具此前是坏的**，见下），得到八个平衡旋钮的影响力排序

## 1 八个旋钮的影响力

| 旋钮 | 平均利润摆动 |
| --- | ---: |
| 售价 | 31996 |
| 配件成本 | 28688 |
| 客群上限 | 3160 |
| 渠道折扣深度 | 2070 |
| 员工工资 | 1680 |
| 装配工时 | 1461 |
| 租金 | 1080 |
| **设计工时** | **0** |

**设计工时是唯一一个动它也不影响利润的旋钮。** ±10% 的变动对三条路线都没有任何影响

## 2 这正是决策 1 的症状

精品路线的整个前提是「**老板的 96 小时设计工时是硬约束，任何投资都买不到**」。而敏感度分析说：**动它没用** ✗

也就是说，**出厂数据下精品路线根本没有被工时约束住**

## 3 实测「工时倍率 → 利润」的响应曲线

| 工时倍率 | 现状（10/18 小时） | 决策 1（14/32 小时） |
| --- | ---: | ---: |
| ×1.0 | 28324 | 28324 |
| **×1.1** | **28324（无变化）** | **24263（−4061）** |
| ×1.2 | 28324 | 24263 |
| ×1.4 | 28324 | 24263 |
| ×1.6 | 28324 | 24263 |
| ×2.0 | 24263 | 12077 |

**读法**：

| 配置 | 工时从 ×1.0 到 ×1.6 的行为 |
| --- | --- |
| **现状** | 一直 28324，**到 ×2.0 才开始有反应** ✗ 说明有 60% 的余量 |
| **决策 1** | 到 ×1.1 就有反应（−4061），之后持平 | ✓ **说明已经吃满** |

**决策 1 把「毫无弹性的旋钮」变成了「稍微一动就疼的旋钮」** ✓ 这正是它要做的
