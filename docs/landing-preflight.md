# 落地预检

六项决策尚未获批，所以数据未改。但**落地会发生什么**已经可以完整预演——用 `experiment.cjs` 套上决策跑一遍，数据在 `finally` 里还原

## 1 预检发现一个真问题

第一轮预检 27 个校验，**24 通过、2 失败**：

| 校验 | 为什么失败 |
| --- | --- |
| `investments` | 招人事实需要重写——**这是预期内的**，落地脚本会做 |
| **`doc-figures`** | **文档里的数字会变成过时** |

第二条是真问题：文档现在引用的是**当下**的数值，一旦落地就变成了旧值

### 具体是 11 处，分布在 3 个文档

| 文档 | 处数 | 例子 |
| --- | ---: | --- |
| `decisions.md` | 9 | 34971 → 34971、56983 → 56983 |
| `era-trends.md` | 1 | 37174 → 37174 |
| `staff-value.md` | 1 | 56983 → 56983 |

这些是**当初的估算值**与**实际落地值**之间的差——模型几经修改后差了几个币

## 2 已修：落地脚本连带刷新文档数字

`check-doc-figures.cjs` 新增 `repair()`：**只改「与当前实测相差 60 以内」的数字**，豁免清单里的不动

`apply-decisions.cjs` 在写数据之后、跑校验之前调用它，并**逐条打印改了什么**

## 4 顺带修的一处

落地脚本原先只跑 24 个校验（当时的总数），**漏了后加的 `doc-figures` 与 `single-source`**。已补上，现在跑全部 27 个——其中一个正好是本次预检失败的校验

## 5 落地现在真正是一步

| 步骤 | 谁做 |
| --- | --- |
| 写入 13 处数值改动 | 脚本 |
| 刷新 11 处文档数字 | 脚本 |
| 重写招人实测事实 | 脚本 |
| 重跑 27 个校验 | 脚本，**不全过就停下** |
| 更新回归基线 | 脚本，**只在校验全过后** |
| 改写两节结论（扩产作废、三难已解） | **人工**，脚本做不了 |
