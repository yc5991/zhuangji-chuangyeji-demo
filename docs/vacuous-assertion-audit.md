# 审计「可能空跑」的断言

第 113 轮我在自己新建的校验里发现一个**静默失效的探针** ✗ ——因为大小写不匹配而从未运行 ✓

**这类失败模式值得系统查一遍**：一个「看起来在检查、实际什么都没检查」的断言 ✓

## 1 扫描方法

在 28 个校验文件里找**循环内的断言** ✓ ——**如果集合为空，循环体一次都不跑，断言全部落空** ✗

## 2 结果

| 项 | 数量 |
| --- | ---: |
| 循环内断言 | 47 |
| 其中集合长度**未被断言**的 | **21** ✗ |

**47 处里 21 处可能在集合为空时什么也不检查** ✓

## 3 但不是 21 处都需要修

**有些集合合法地可以为空** ✗ 例如 `schedule.openGaps` ✓ ——全部缺口解决后它就是空的 ✓

**加非空断言会误报** ✓

**所以只处理「集合为空就等于这个文件什么都没检查」的那几处** ✓

| 文件 | 集合 | 为空意味着 |
| --- | --- | --- |
| `check-case-options.cjs` | `model.groups` | 机箱定制完全没有被检查 |
| `check-cable-routing.cjs` | `definedRoles` | 理线角色完全没有被检查 |
| `check-design.cjs` | `balance.weights` | 评分权重完全没有被检查 |
| `check-design.cjs` | `workbench.eventDates` | 配件上市节点完全没有被检查 |
| `check-reliability.cjs` | `recipes` | 故障率与配方完全没有被对照 |
| `check-schedule.cjs` | `events.events` | 市场事件完全没有被检查 |

**这 6 处已加非空断言** ✓ 其余 15 处保持原样，因为它们合法地可以为空 ✓

## 4 实测

加上 6 条断言后：**28 个校验全部通过** ✓ ——说明这些集合当前都非空 ✓ 而**今后若变空，会立刻失败** ✓

## 6 一个未解决的问题

**没有把它们做成自动检查** ✓ 因为「这个集合是否合法为空」是语义问题，不是语法问题 ✗ ——与第 111 轮 `openGaps` 的边界同类 ✓
