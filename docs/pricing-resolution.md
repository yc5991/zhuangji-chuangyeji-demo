# 决策 1 与决策 2 的冲突，以及它的解法

## 1 冲突

第 44 轮建议「静音办公高定停在 5100」，理由是抬价会让困难档在需求下降 35% 的场景下第 1 月破产

本轮把两项决策合起来测，发现**这个建议会打破路线规则**：

| 配置 | 精品 | 量产 | 混合 | 混合最高 |
| --- | ---: | ---: | ---: | --- |
| 已提交数值 | 28324 | 31314 | 37008 | 是 |
| 原方案（高定也抬价） | 34971 | 37174 | 37709 | 是 |
| **停在 5100** | 32359 | 37174 | **35387** | **否** |

原因是**混合也生产静音办公高定**，不抬它的价，混合就掉到量产下面

## 2 逐点扫描：两个要求没有交集

把静音办公的价格从 5100 逐点往上扫：

| 价格 | 混合最高 | 困难×降需35 第 1 月 |
| ---: | --- | --- |
| 5100 | **否** | 存活 |
| 5150 | 否 | **破产** |
| 5300 | 否 | **破产** |
| **5350** | **是** | **破产** |
| 5391 | 是 | **破产** |

**「混合最高」要到 5350 才成立，「第 1 月存活」在 5150 就失效——两个窗口不重叠**

## 3 试过的三条路都不通

| 尝试 | 结果 |
| --- | --- |
| 停在 5100 | 混合掉到量产下面 ✗ |
| 提高困难档开局现金到 3000 | **无效**——第 1 月造 0 台，只是把钱亏掉 ✗ |
| 订单取整改成四舍五入 | 悬崖消失，但**量产多赚 1701**（囤货卖出去了），混合永远不再是最高 ✗ |

第三条尤其值得记下来：**取整不是问题的根源**，根源是「可达订单恰好为 1」时接受度被归零。改取整只是把问题搬到别处

## 4 真正的解法：抬高这一个客群第 1 月的需求上限

静音办公高定的月上限是 `[2,3,4,5,6,6]`。需求下降 35% 后变成 `[1,2,3,3,4,4]`——**第 1 月恰好是 1 单**，于是接受度 0.829 被 `floor` 归零

**只要把第 1 月从 2 抬到 3**（变成 `[3,3,4,5,6,6]`）：降需后第 1 月是 2 单，接受度 0.829 × 2 = 1.658，`floor` 后是 **1 单** ✓

| 静音办公上限 | 困难×降需35 第 1 月 | 混合最高 | 精品<量产 |
| --- | --- | --- | --- |
| `[2,3,4,5,6,6]`（现状） | **破产** | 是 | 是 |
| **`[3,3,4,5,6,6]`** | **存活** | 是 | 是 |
| `[3,4,5,6,6,6]` | 存活 | 是 | 是 |

**只改一个数字就解决了**，不需要动价格、取整或开局现金

## 5 合并配置的完整验证

**配置**：方案的高定工时（静音办公 14/20、创作 32/45）+ 方案的价格（2202 / 4743 / **5391** / 11724）+ 静音办公月上限 `[3,3,4,5,6,6]`

| 检查项 | 结果 |
| --- | --- |
| 精品 < 量产 | 34971 < 37174 ✓ |
| 混合最高 | 37709 ✓ |
| 混合 < 精品 + 量产 | ✓ |
| 困难档解锁时点 | 第 4 月末（累计交付 5 台） |
| 困难档精品第 6 月 | 仍有 `CAPACITY_LIMIT:premium`（决策 1 想要的效果） |
| **全部难度 × 路线 × 场景的第 1 月** | **全部存活** |

## 6 对决策 2 的修正

**第 44 轮建议的「静音办公高定停在 5100」应当撤回。** 正确做法是：

- 价格照原方案抬到 **5391**
- **同时把静音办公高定的第 1 月需求上限从 2 抬到 3**

这样既保住三条路线规则，又让困难档在压力场景下能开局
