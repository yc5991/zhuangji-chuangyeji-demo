# 可达性

分项校验检查数值是否合规，但合规不等于做得到。`npm run check:reachability` 检查每一档难度乘每一条路线是否真的能跑起来，以及计划里的每一笔开支是否付得起

## 1 检查四项

**① 开局必须能开工**：每一档难度、每一条可用路线，第 1 月必须至少造出 1 台，且不能出现 `DEVELOPMENT_BLOCKED`。造不出东西的运行不算可玩

**② 开发费的归属**：定型机必须有开发费；**委托是一次性制作，不应带开发费**。两个方向都验证，防止将来把委托误标成定型机而多收一笔钱

**③ 计划里的开支必须付得起**：路线计划里排期的每一项投资，到那个月必须真的买得起（出现 `EXPANSION_UNAFFORDABLE` 就记下来）

**④ 计划完成率**：普通与简单档至少完成计划的 90%；困难档允许达不到，但整轮不能一台都造不出来

## 2 实测结果

| 难度 | 路线 | 第 1 月产量 | 计划完成率 |
| --- | --- | ---: | ---: |
| 简单 | 精品 / 量产 / 混合 | 1 / 7 / 5 | 100% / 100% / 98.6% |
| 普通 | 精品 / 量产 / 混合 | 1 / 7 / 5 | 100% / 100% / 98.6% |
| 困难 | 精品 | 1 | **60%** |

困难档只完成 60% 是预期内的——它被采购现金上限拦住四次。简单与普通档接近满产，说明它们的计划不受约束

## 3 查出的问题：困难档精品买不起自己计划里的投资

精品路线的计划在第 3 月购买精细工艺工具（1200），但困难档第 3 月末只有 **863** 现金——**这项投资从来没被买到过**

| 配置 | 难度 | 第 3 月现金 | 买得起 | 最早买得起 |
| --- | --- | ---: | --- | --- |
| 当前已提交 | 简单 | 52570 | 是 | 第 1 月末 |
| 当前已提交 | 普通 | 35303 | 是 | 第 1 月末 |
| **当前已提交** | **困难** | **863** | **否** | **第 5 月末** |
| 五项方案落地后 | 简单 | 54785 | 是 | 第 1 月末 |
| 五项方案落地后 | 普通 | 37519 | 是 | 第 1 月末 |
| **五项方案落地后** | **困难** | **4769** | **是** | **第 2 月末** |

**五项方案顺带修好了这个问题**：落地后困难档第 2 月末就能买得起，第 3 月按计划购买时不再是空头支票

## 4 关于委托不带开发费

两套高定（静音办公高定、静音创作高定）的 `kind` 是 `commission`，**没有开发费字段是设计如此**——委托是客户下单后的一次性制作，不需要先开发一个可复用的定型产品。校验会同时验证两个方向，避免将来误标导致多收一笔钱

## 5 与决策 3 的关系

困难档解锁量产需要的开发费是 **300**（办公 120 + 游戏 180；两套高定是委托，不需要开发费）

累计交付 5 台高定的解锁时点**取决于哪套数值在跑**：

| 配置 | 达到 5 台交付 |
| --- | --- |
| 当前已提交数值 | 第 **5** 月末 |
| 五项方案落地后 | 第 **4** 月末 |

决策包写的第 4 月末是**方案落地后**的数字，两者是一致的
