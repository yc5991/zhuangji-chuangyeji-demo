# 对照实验脚手架

第 52、53、54 轮连续出现**归因错误**，共同的根源是「用一个局部测量推出全称结论」。而做对照实验又会碰到一个操作风险：

> **实验脚本改了数据文件，然后在中途崩溃，数据被留在实验状态。**

第 54 轮就发生过一次：验证取整悬崖的脚本在 `require` 阶段抛出断言，**崩溃点在恢复语句之前**，数据文件被留在「方案价格」的状态

## `tools/experiment.cjs`

为此写了一个小脚手架，把「改数据 → 测量 → 恢复」变成一个原子操作：

    const { experiment } = require('./experiment.cjs');
    experiment({ 'economy-candidate.json': { products: { quiet_office: { salePrice: 5391 } } } },
      ({ simulate }) => { ...测量... });

三件事：

| 特性 | 说明 |
| --- | --- |
| **深合并** | 只改写明的字段，其余不动——这正是「只改一个变量」的形式化 |
| **`finally` 恢复** | 无论正常结束还是抛异常，数据都会写回 |
| **清缓存** | 恢复后清掉 `tools/` 的 `require` 缓存，后续导入看到的是恢复后的数据 |

另有 `sweep(variants, measure)` 一次跑多个变体

## 实测

**用第 44 轮的取整悬崖做例子**（只改一个价格）：

| 变体 | 第 1 月交付 | 第 1 月期末现金 | 破产 |
| --- | ---: | ---: | --- |
| 原价 5100 | 1 | +280 | 无 |
| 静音办公 5391 | **0** | **−1700** | **第 1 月** |

**第三次确认了第 44 轮的结论**，而且这次是脚手架自动做完恢复的

## 崩溃恢复测试

在测量函数中途主动抛异常：

    实验进行中的价格: 9999
    捕获到异常: 模拟测量中途崩溃
    崩溃后的价格: 5100 ✓ 已恢复

**这正是第 54 轮缺少的那条保证。**

## 与校验的分工

| 工具 | 用途 |
| --- | --- |
| `tools/experiment.cjs` | **回答「如果改成 X 会怎样」**，用完就还原 |
| `tools/apply-decisions.cjs` | **把确认的决策真正写进去**，并重跑校验与基线 |
| `tools/preview-proposal.cjs` | 用 `simulate` 的参数覆盖做预览，不碰数据文件 |

三者都改不坏工作区：前者靠 `finally`，中者靠「校验全过才更新基线」，后者根本不碰文件
