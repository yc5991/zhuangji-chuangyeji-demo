# 「玩家对市场做出反应」机制草案

**合并决策 5、决策 E、以及第 82 轮查出的另外两种应对。** 这是第 83 轮的建议实现方案，待你确认

## 1 为什么合并

四处设计文本说的是同一件事：

| 来源 | 原文 |
| --- | --- |
| `market-events.json` | 玩家在预兆期可以「提前备货、换更便宜的容量档、给受影响样机调价，或者接受风险」 |
| `market-events.json` | 「玩家提前备货要占用资金并承担落空风险」 |
| 决策 5 | 玩家在月结前调整下月排产数量 |
| `demo-schedule.json` | 第 3—4 月「玩家可以调整配置、接受较低利润、修改售价、改变定位或放弃不合适的订单」 |

**四处都在说：玩家必须能对市场变化做出反应。** 而参考仿真器**一种反应都不支持**

## 2 四个维度的实测可行性

| 维度 | 可行性 | 实测效果 |
| --- | --- | --- |
| **调整产量** | ✅ 可行 | **量产在需求下降 35% 时：破产 → 存活，利润 13217 → 14741（+11%）** |
| **提前采购** | ✅ 可行 | **困难档精品碰上内存明显上涨：破产 → 存活，末期现金 −2961 → +9186** |
| 调整售价 | ⚠️ 受限 | 价格已在天花板附近，空间很小；且降价对混合路线的伤害大于对量产的帮助 |
| 换容量档（内存） | ❌ **不可行** | 见下 |
| 换容量档（固态） | ✅ 可行 | 每台最多省 120 币，相对 8000+ 的摆动可忽略 |

### 内存为什么不能降档

| 产品 | 现有内存 | 客群最低要求 | 能否降 |
| --- | ---: | ---: | --- |
| 预算办公 | 8GB | 8GB（学生/家庭/办公） | **不能** |
| 主流游戏 | 16GB | 16GB（玩家） | **不能** |
| 静音办公高定 | 8GB | 8GB（静音专业） | **不能** |
| 静音创作高定 | 16GB | 16GB（创作者） | **不能** |

**四个产品的内存都恰好等于客群要求的下限。** 所以「换更便宜的容量档」这条在内存维度上**物理上做不到**——降了就没人买

### 固态可以降一点

| 产品 | 现有固态 | 客群要求 | 可降到 | 每台省 |
| --- | ---: | ---: | ---: | ---: |
| 主流游戏 | 250GB | 无要求 | 120GB | 120 币 |
| 静音办公高定 | 250GB | 无要求 | 120GB | 120 币 |
| 预算办公 | 120GB | 120GB | — | 0 |
| 静音创作高定 | 500GB + 1TB | 1000GB | 500GB 可换小 | 少量 |

**每台省 120 币，相对内存事件的 8000+ 摆动可以忽略。**

## 3 建议的实现范围：两个维度

### 3.1 提前采购（决策 E）

| 项目 | 内容 |
| --- | --- |
| **何时可用** | 事件的预兆月（第 3 月） |
| **能做什么** | 按当时的市价采购额外配件，存入库存，供后续月份生产使用 |
| **代价** | 占用现金；若传闻落空，这批配件占用的资金就是损失 |
| **实测效果** | 困难档精品从「第 5 月必死」变成「末期现金 +9186」 |
| **设计意图** | 让「预兆」成为可据以行动的信息，而不是一条新闻 |

### 3.2 调整排产（决策 5）

| 项目 | 内容 |
| --- | --- |
| **何时可用** | 每月结算前 |
| **能做什么** | 修改下月各机型的计划生产数量 |
| **代价** | 无直接代价，但判断错误会积压或缺货 |
| **实测效果** | 量产在需求下降 35% 时从破产变成 +14741；**不改则与现状完全相同** |
| **设计意图** | 让第 78 轮测出的「风险画像」变成可操作的信息 |

### 3.3 不实现的两项

| 维度 | 为什么不实现 |
| --- | --- |
| **换内存容量档** | 物理上不可行——四个产品的内存都等于客群下限 |
| **调整售价** | 价格已在天花板附近（两个高定的最优价距硬墙只有 13/37 币），降价又伤混合路线。**留作设计余量，不做成事件应对手段** |

**因此 `market-events.json` 的 `playerCanReactDuringOmen` 文本需要修改**：从四项改为「提前备货，或者接受风险」

## 4 对现有数值的影响

**零影响。** 两个维度都是**玩家可选的额外操作**：

- 不调产量 = 现在的数值
- 不提前采购 = 现在的数值

**所以这套机制可以安全加入，不需要重新标定**

## 5 需要实现的仿真器改动

| 改动 | 规模 |
| --- | --- |
| 允许 `monthlyProductionTargets` 按月修改 | 小——参数已经是逐月数组 |
| 允许在预兆月按当时价格买入库存 | 中——需要库存与采购价格的时间维度 |
| 允许库存配件用于后续月份生产 | 中——同上 |

**前两项是设计层确认；第三项属于工程实现**
