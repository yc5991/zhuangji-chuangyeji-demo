# 品质评分改成**顾客评价制**（像美团商家评分）

## 你的规则

> 「这个系统肯定是**用户对你的店铺进行随机评分**……满足正常要求：只要达到要求，肯定会给你 3 分以上。超额完成：就有可能给你 5 分。未完成或处理不好：肯定会给你低评分。**这个评分是随机跳动的。**」

## 我原来做错的地方

上一轮我把刻度改成了 1—5 分 ✓ 但**机制**还是旧的「每个月固定加减一个数」✗ ——那不是评分 ✓ 那是分数调整 ✓

**你要的是一套评价系统**：

| 项 | 旧做法 ✗ | 新做法 ✓ |
| --- | --- | --- |
| 口碑怎么变 | 每月 +0.6 / −0.3 / −1.2 | **每交付一台，顾客留一条评价** |
| 口碑是什么 | 累加出来的数 | **所有评价的加权平均** |
| 会不会跳动 | 不会，只是单调爬升 | **会**——单子越多越难被少数几条拉起来 |

## 评价分布

| 情形 | 1 分 | 2 分 | 3 分 | 4 分 | 5 分 | 平均 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| **达标** | — | — | 40% | 40% | 20% | **3.8** |
| **超额完成** | — | — | 10% | 40% | 50% | **4.4** |
| **迟交** | — | 50% | 50% | — | — | **2.5** |
| **让客户失望** | 40% | 60% | — | — | — | **1.6** |

**正好符合你说的三条**：达标必定 3 分以上 ✓ 超额才有大量 5 分 ✓ 没做好必定低分 ✓

**「超额完成」怎么判定**：机器的外观**高于客户心里的参考值**就算 ✓ 用的是设计里已有的 `appearancePreference.baselineScore` ✓

## 店铺评分的算法（与外卖平台同一套）

    评分 = (开局权重 × 1 + 所有评价之和) ÷ (开局权重 + 评价条数)

**开局权重 = 3** ✓ 意思是「开业时按 3 条 1 分算」✗ **等价于「没有记录就不该有好名声」** ✓ 它决定新店要接多少单才能把分拉上来 ✓

## 实测：口碑的逐月轨迹（普通档）

| 路线 | 轨迹 |
| --- | --- |
| 精品 | 1.70 → 2.40 → 2.75 → 3.04 → 3.20 → **3.33** |
| 量产 | 2.87 → 3.33 → 3.53 → 3.63 → 3.68 → **3.71** |
| **混合** | 2.87 → 3.36 → 3.54 → **3.19** → 3.37 → **3.15** |

**三个现象都对**：

1. **精品爬得慢** ✓ 单少 ✓ 平均被开局权重拖着走 ✓
2. **量产爬得快** ✓ 单多 ✓ 评价多 ✓
3. **混合会往下跳** ✓ 它有迟交的月份 ✓ **这就是「随机跳动」** ✓
