## 顺带查出并修好了一个校验缺陷

数据搬进去之后，`check:design-to-game` 报告**「已知缺口全部消失」** ✗ ——但游戏里**一行故障逻辑都还没有** ✓

### 两个原因

| # | 缺陷 | 后果 |
| --- | --- | --- |
| 1 | 实现探测**包含了生成的 `data.ts`** | 数据一搬进去，名字就出现在探测范围里，于是「已携带」被误认成「已实现」 ✗ |
| 2 | 判定条件是「**携带 或 实现**」 | 只要携带了就不再报缺口 ✗ 而这条规则要的是**实现** ✓ |

## 已修

| 改动 | 内容 |
| --- | --- |
| 探测排除 `data.ts` | 生成的 data 携带的是**模型自己的值** ✗ 拿它当实现证据等于什么都没验 ✓ |
| 条件改为「**携带 且 实现**」 | 规则必须被游戏的**逻辑**命名才算实现 ✓ |

**修完后校验正确地重新报出缺口** ✓ 说明它真的在检查东西 ✓
