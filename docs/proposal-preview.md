# 方案预演

五项待定决策现在各有一个实测方案。`npm run preview:proposal` 在**不改动任何已提交数据**的前提下，用仿真器的覆盖参数把方案整体跑一遍，逐条检查不变量

结果写入 `.local/proposal-verification.json`。这是「你说做之后会得到什么」的证据，而不是承诺

## 2 预演通过的不变量

| 不变量 | 结果 |

| 难度顺序（24 组比较） | ✅ 无倒挂 |
| 可承受亏损月数 | ✅ 18.96 / 2.87 / 1.61，顺序正确 |
| 投资必须回本 | ✅ 五项全部回本 |

| 十五年全程不亏损 | ✅ 最低 56231 |

困难档的量产与混合被标记为开局锁定，预演会跳过它们，不做无意义的比较

## 3 方案带来的最大改善：投资从「全是弱决策」变成「全是好决策」

第 6 轮查出所有发展投资的回报率只有 1.00—1.20，属于弱决策。方案落地后：

| 投资 | 现在 | 方案 |
| --- | ---: | ---: |
| 精品 精细工艺工具 | 1.20 | **5.05** |
| 量产 增加装配台 | 1.01 | **1.93** |
| 量产 半自动装配设备 | 1.05 | **2.55** |
| 混合 精细工艺工具 | 1.00 | **3.35** |
| 混合 增加装配台 | 无 | **4.87** |

原因是混合路线在第 5 月新增的装配台真正解锁了被产能挡住的产量，所以回报率高达 4.87；而精品被老板工时封顶，投资回报率反而是最高的 5.05——因为工艺工具降低的是它唯一受限资源的消耗

## 4 与其他校验的关系

`preview:proposal` 用的是仿真器覆盖参数，**不写入任何 design 文件**，所以：

- 十三个 `check:*` 与 `baseline:diff` 仍然针对**当前已提交的数值**，全部保持通过
- 方案是否落地由 `docs/decisions.md` 的确认决定，不由预演决定

确认后我会把方案写进 `design/economy-candidate.json` 等文件，重新生成基线，并给出前后对比
