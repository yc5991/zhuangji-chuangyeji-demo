# 文档数字与数据一致

第 59 轮发现完成度审计里的数字是过时的，说明**同类问题可能存在于别的文档**。本轮扫描全部 60 份文档，证实了这一点

## 1 查法

先从仿真器取当前实测的七个路线利润，再扫描文档里**与某个实测值相差 60 以内但不相等**的四到六位数字

**「相近但不相等」是关键**：一个真正的旧版抄本会与原值只差几个币（比如 28329 与现在的 28324），而无关的数字不会恰好落在这个窗口里

## 2 查出 19 处过时数字，分布在 6 个文档

| 文档 | 处数 | 例子 |
| --- | ---: | --- |
| `design-candidates.md` | 5 | 28329 / 31345 |
| `era-trends.md` | 6 | 37028 / 33441 / 40599 |
| `decisions.md` | 4 | 28329 / 31345 / 40607 |
| `landing-checklist.md` | 3 | 28329 / 31345 / 37028 |
| `sensitivity.md` | 3 | 28329 / 31345 / 37028 |
| `staff-value.md` | 1 | 7688 |

旧值都是第 34—56 轮之前的数字，与现在的实测只差几个币

## 3 第一次修错了——整篇替换会破坏真实内容

我最初做的是**全文替换**（把 28329 全改成 28324 等），结果**改坏了两个文档**：

| 文件 | 被误改的内容 | 为什么不该改 |
| --- | --- | --- |
| `staff-value.md` | `−7688` → `−7686` | 那是**招人造成的亏损**，不是困难档利润 |
| `era-trends.md` | 2021 年的 `36950` → `37008` | 那是**年代模型下 2021 年的混合利润**，不是 2016 基准 |

**已从 git 还原这两个文档，改为逐行指定修改**（只改确实引用 2016 基准利润的行），共 32 处

## 4 有意保留的数字（7 处）

| `staff-value.md` / `decisions.md` | −7688 | **招人造成的亏损** |
| `decisions.md` | 40607 | 已撤回的 A 方案**当时会产生的**量产利润 |

## 5 新增 `npm run check:doc-figures`

把这条检查固定下来：**文档里不得出现与当前实测相差 60 以内的数字**，除非在豁免清单里写明理由

这样以后改模型时，**忘记同步文档会当场失败**，而不是等到几十轮后被发现
