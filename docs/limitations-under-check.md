### 为什么允许「不可检查」

与第 111 轮处理 `openGaps` 同理 ✓ **假装能判定会误报，误报会被忽略** ✗ 明确标注则至少保证「新加一条限制时，必须选择探针或标注」✓

## 2 我在自己这条校验里踩了两个坑

### 坑一：探针匹配到了「限制文本自己」

第一次运行报错：

    limitation #3 says returns is not simulated, but it is

**因为 `returns` 这个词只出现在限制语句本身里** ✗ 探针搜的整个文件包含了那句限制 ✓

**已修**：探测前把 `limitations` 数组替换掉 ✓

### 坑二：大小写不匹配导致探针**静默跳过**

我加了 `leadTime` 做测试，检查**没有报错** ✗

**原因**：限制文本写的是 `Lead times`（首字母大写）✗ 而我在表里写的是 `lead times` ✗ `includes` 区分大小写 ✓ 于是探针**从未运行** ✓

**这正是这条校验要防的失败模式**：一项检查静默地什么都没检查 ✓

**已修两处**：

1. 匹配改为大小写不敏感 ✓
2. **加了「探针必须跑到」的断言**——若某项的探针因名字不匹配而跳过，直接失败 ✓
